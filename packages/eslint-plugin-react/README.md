# @noctcore/eslint-plugin-react

React architecture and correctness rules: unmemoized context values, effects without cleanup, state
derived in effects, and components that grow past what one file should hold.

**Docs:** [noctcore.github.io/eslint-plugins/packages/react](https://noctcore.github.io/eslint-plugins/packages/react/)

Not a good fit for a codebase that keeps hooks inline by convention, or a library of generic
primitives where wide prop surfaces are the point.

## Requirements

- ESLint 9 or 10, flat config (`eslint.config.js`) only.
- `configs.recommended` registers the plugin and sets rule severities, nothing else. It sets no
  `files` and no parser, so it applies to whatever files the rest of your config lints. To lint
  TypeScript, add a `files` pattern and `@typescript-eslint/parser`, as in the quick start.

## Install

```sh
bun add -D @noctcore/eslint-plugin-react @typescript-eslint/parser   # or npm i -D / pnpm add -D
```

## Quick start

```js
// eslint.config.js
import tsParser from '@typescript-eslint/parser';
import react from '@noctcore/eslint-plugin-react';

export default [
  {
    ...react.configs.recommended,
    files: ['**/*.{ts,tsx}'],
    languageOptions: { parser: tsParser },
  },
  // Optional: tune a preset rule's options.
  {
    files: ['**/*.{ts,tsx}'],
    rules: {
      'noctcore-react/no-prop-drilling': ['error', { maxForwarded: 4 }],
    },
  },
];
```

## Strict preset

`configs.strict` is `recommended` plus the house rules: `component-props-naming`, `max-hook-return-surface`, `max-hooks-per-file`, `max-props-per-component`, `max-state-per-hook`, `no-jsx-computation`, `no-state-in-component-body`. A house rule holds in a codebase
that follows the same convention and reports widely in one that does not, so it is one spread away
instead of on by default.

They are this house's React conventions, not defects every codebase has: a props naming scheme
(`component-props-naming`), size caps (`max-*`), and a thin component shell that keeps state and
list rendering out of the component body (`no-state-in-component-body`, `no-jsx-computation`).

```js
// eslint.config.js
export default [
  {
    ...react.configs.strict,
    files: ['**/*.{ts,tsx}'],
    languageOptions: { parser: tsParser },
  },
];
```

**Upgrading to 1.0:** `recommended` no longer turns on `component-props-naming`, `max-hook-return-surface`, `max-hooks-per-file`, `max-props-per-component`, `no-jsx-computation`, `no-state-in-component-body`. To keep the 0.x behaviour, spread
`configs.strict` where you spread `configs.recommended`, or enable the rules you want one by one.

## Opt-in rules

Two rules are left out of `recommended`: `enforce-context-consumption` does nothing until its
`contexts` registry is set, and `no-native-date-input` enforces a house convention (use the design
system's date picker) rather than a defect every codebase has.

```js
// eslint.config.js
export default [
  // ...the quick start's entries, then:
  {
    files: ['**/*.{ts,tsx}'],
    languageOptions: { parser: tsParser },
    rules: {
      'noctcore-react/enforce-context-consumption': ['error', {
        contexts: [{
          hook: 'useTaskActions',
          files: ['src/components/board/**'],
          providedProps: ['onRun', 'onCancel', 'onDelete'],
        }],
      }],
      'noctcore-react/no-native-date-input': ['error', {
        replacement: '`DateField` from `@/shared/components/DateField`',
        allowIn: ['**/DateField/**'],
      }],
    },
  },
];
```

## Severity policy

Every rule is `error` or `off`, never `warn`: a warning is a rule nobody obeys. See the
[severity policy](https://noctcore.github.io/eslint-plugins/getting-started/#severity-policy).
