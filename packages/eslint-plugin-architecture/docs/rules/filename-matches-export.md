# `noctcore-architecture/filename-matches-export`

> A file's basename must match its primary export (a default export, or the sole named export).

<!-- begin generated rule header -->
☑️ In `strict` at `error`, not in `recommended` · 💡 Offers editor suggestions · 💭 Type information: not needed
<!-- end generated rule header -->

## In short

When a file has one clear export, its name must say what that export is. `helpers.ts` exporting only
`formatDate` is reported, and case and separators never count, so `format-date.ts` matches
`formatDate`.

`{{basename}}` is the file's name, `{{name}}` the primary export and `{{expected}}` the name the other
side should take. `renameExport` is the editor suggestion that renames the export.

## Code that triggers it

When a module has one clear public export, the filename should announce it. A `helpers.ts` that
exports a single `formatDate` hides its contents from anyone scanning the file tree, and a rename of
one without the other leaves the two permanently out of sync. Keeping them aligned makes the tree
self-describing.

The rule first resolves the file's **primary export**:

1. If the file has a default export with a name (`export default function Foo`, `export default
   class Foo`, `export default Foo`), that name is the primary export. An anonymous default
   (`export default () => …`) has no identifier to compare, so the file is skipped.
2. Otherwise, if the file has exactly one local named export, that is the primary export.
3. Otherwise (no primary, or several named exports) the file is skipped.

### A file named for something else

```ts bad message=filenameMismatch,renameExport filename=src/utils/helpers.ts
// genuine mismatch
export const formatDate = () => {};
```

**The fix:** rename the file after the export. The basename and the identifier are compared case- and
separator-insensitively, so a kebab-case file matches a camelCase export.

```ts good filename=src/utils/format-date.ts relocation
export const formatDate = () => {};
```

### Renaming the export instead

The same mismatch, fixed from the other side.

```ts bad message=filenameMismatch,renameExport filename=src/utils/helpers.ts
export const formatDate = () => {};
```

**The fix:** rename the export to the filename. This is the change the editor suggestion makes.

```ts good filename=src/utils/helpers.ts
export const helpers = () => {};
```

### Suggestion, not autofix

A mismatch offers a **suggestion** to rename the export to the filename (the code-side resolution;
the other is renaming the file). It is never an autofix: renaming a public identifier is a decision a
human should confirm. When the basename is not a valid identifier (e.g. `2fa.ts`), the mismatch is
reported without a suggestion.

```ts bad message=filenameMismatch filename=src/auth/2fa.ts
export const verifyCode = () => {};
```

**The fix:** rename the file, since no identifier can be named `2fa`.

```ts good filename=src/auth/verify-code.ts relocation
export const verifyCode = () => {};
```

## What it does not flag

- `index` files and files matching an `allowIn` glob.
- A file with no primary export: an anonymous default (`export default () => 1`), several named
  exports and no default, or no exports at all.
- A pure re-export (`export { Foo } from './Foo'`), which has no local identity.
- A file whose default export matches, even when it also has other named exports.

The comparison ignores case and separators:

```tsx good filename=src/components/TaskCard.tsx relocation
export default function TaskCard() {}
```

```ts good filename=src/hooks/use-thing.ts relocation
// kebab-case file, camelCase export
export const useThing = () => {};
```

## Options

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `allowIn` | `string[]` | `[]` | Globs (supporting `**`, `*`, `?`) of files to skip. |
| `ignore` | `string[]` | (none) | Deprecated alias of `allowIn`, kept through 1.x. When both are set, their globs are combined. |

```js
'noctcore-architecture/filename-matches-export': ['error', {
  allowIn: ['**/*.stories.tsx', '**/route.ts'],
}]
```

## When not to use it

If your files routinely export several unrelated symbols, or you use fixed conventional filenames
(`route.ts`, `handler.ts`) that will never match their export, add them to `allowIn` or leave the rule
off.
