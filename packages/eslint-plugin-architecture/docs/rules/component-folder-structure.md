# `noctcore-architecture/component-folder-structure`

> A component entry file must ship its full sibling set (hooks, types, story, test, barrel) on disk.

<!-- begin generated rule header -->
☑️ In `strict` at `error`, not in `recommended` · 💭 Type information: not needed
<!-- end generated rule header -->

## In short

A component is a folder, not a lone `.tsx`. Its entry file `<Name>/<Name>.tsx` must sit beside its
hooks, types, story, test and `index.ts` barrel on disk, and the rule names every sibling that is
missing.

## What you will see

<!-- begin generated messages -->

- `missingSiblings`: Component `{{name}}` is missing sibling file(s): {{missing}}. Every component folder must carry its hooks, types, stories, test, and index barrel.
- `notInOwnFolder`: Component `{{name}}` is not in its own folder. Move it to `{{name}}/{{name}}.tsx` alongside its sibling set ({{required}}).
<!-- end generated messages -->

`{{name}}` is the component, `{{missing}}` the siblings not found on disk and `{{required}}` the
whole `requiredSiblings` set.

## Code that triggers it

In a folder-per-component layout, when the logic (`.hooks.ts`), the types (`.types.ts`), the story
(`.stories.tsx`), the test (`.test.tsx`), and the `index.ts` barrel always travel with the component,
refactors stay local and nothing is quietly untested or undocumented. This rule enforces that
colocation by construction.

A sibling missing on disk is reported on the entry file. A second panel shows components/splash/SplashRain.tsx, a component file outside a folder of its own, which the requireOwnFolder option reports with a move to SplashRain/SplashRain.tsx.](../diagrams/component-folder.svg "The entry file is checked against **the folder around it**: five siblings by default, each one a file on disk.")

For every **component entry file**, a PascalCase `.tsx` whose basename equals its parent folder
(`TaskCard/TaskCard.tsx`) and that lives under the configured `componentRoot`, the rule reads the
component's directory and reports any sibling from the required set that is missing on disk. The
report sits on the file's first line, so an editor does not underline the whole file.

A purely presentational component has no logic to extract, and its `.hooks.ts` ends up as an
`export {};` with a comment. That is the cost of the convention, and it is deliberate: the file
being present means there is one obvious place for logic to go the day the component grows some,
and a reviewer never has to ask where it lives. A project that disagrees drops `.hooks.ts` from
`requiredSiblings` rather than carrying stub files.

### A component folder missing siblings

The examples below lint in a real folder on disk (the doc's `fixture`). In the first,
`components/board/TaskCard/` holds only `TaskCard.tsx` and `index.ts`; in the second it holds the full
set.

```tsx bad message=missingSiblings fixture=docs/component-folder/missing filename=src/components/board/TaskCard/TaskCard.tsx
export default function TaskCard() {
  return null;
}
```

```text report
Component `TaskCard` is missing sibling file(s): TaskCard.hooks.ts, TaskCard.types.ts, TaskCard.stories.tsx, TaskCard.test.tsx. Every component folder must carry its hooks, types, stories, test, and index barrel.
```

**The fix:** add the four missing files next to `TaskCard.tsx`. The component's code does not change;
its folder does.

```tsx good fixture=docs/component-folder/complete filename=src/components/board/TaskCard/TaskCard.tsx
export default function TaskCard() {
  return null;
}
```

### A component outside its own folder (`requireOwnFolder`)

With `requireOwnFolder: true`, a PascalCase `.tsx` under a feature that is **not** the entry file of
its own folder is reported too: a sub-component dropped into another component's folder
(`BulkActionBar/MoreMenu.tsx`) or a loose file at a feature root (`splash/SplashRain.tsx`). The
message asks for the move to `<Name>/<Name>.tsx`, not for siblings, since the file has no folder of
its own yet. Without the option these files are invisible to the rule, which is how they
accumulate. It is off by default because it reports files the sibling check has always left alone.

```text prose reason="a picture of where requireOwnFolder looks"
components/splash/
  SplashRain.tsx        ← reported with requireOwnFolder: not in its own folder
  SplashScene/
    SplashScene.tsx     ← entry file (sibling check)
    SceneLayer.tsx      ← reported with requireOwnFolder: inside another component's folder
```

```tsx bad message=notInOwnFolder fixture=docs/component-folder/loose filename=src/components/splash/SplashRain.tsx options={"requireOwnFolder":true}
export default function SplashRain() {
  return null;
}
```

**The fix:** move the file to `splash/SplashRain/SplashRain.tsx` and give it its sibling set. From
then on the sibling check covers it like any other component.

```tsx good relocation fixture=docs/component-folder/own-folder filename=src/components/splash/SplashRain/SplashRain.tsx options={"requireOwnFolder":true}
export default function SplashRain() {
  return null;
}
```

## What it does not flag

- Files that are not entry files: `task-card.tsx` (not PascalCase) or `Group/Widget.tsx` (basename
  differs from its folder), unless `requireOwnFolder` is on. Sidecars (`Widget.stories.tsx`,
  `Widget.test.tsx`) are never component files.
- Entry files outside the `componentRoot` segment, such as `routes/Widget/Widget.tsx`.
- Files matched by `allowIn`; the default `**/ui/**` keeps the lighter shadcn-style layout.
- A component folder whose siblings cover whatever `requiredSiblings` is set to, even a trimmed set.

### Edits to other files

This rule also reads the component folder's listing, so its result can change when that file does.
`eslint --cache` does not notice and keeps the old result until the linted file itself changes. A
long-running editor server picks up an edit to it, because the rule re-reads it when it changes. See
[Rules that read other files](https://noctcore.github.io/eslint-plugins/filesystem-rules/).

## Options

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `componentRoot` | `string` | `'components'` | The directory segment the layout is anchored on. |
| `requiredSiblings` | `string[]` | `['.hooks.ts', '.types.ts', '.stories.tsx', '.test.tsx', 'index.ts']` | The sibling set. An entry starting with `.` is a name-relative suffix (`.hooks.ts` → `<Name>.hooks.ts`); any other entry is a literal filename (`index.ts`). |
| `allowIn` | `string[]` | `['**/ui/**']` | Globs (supporting `**`, `*`, `?`) of paths to skip. |
| `ignorePaths` | `string[]` | (none) | Deprecated alias of `allowIn`, kept through 1.x. When both are set, their globs are combined. |
| `requireOwnFolder` | `boolean` | `false` | Also report a component file under a feature that is not the entry file of its own folder. |

```js
'noctcore-architecture/component-folder-structure': ['error', {
  componentRoot: 'components',
  requiredSiblings: ['.hooks.ts', '.types.ts', '.stories.tsx', '.test.tsx', 'index.ts'],
  allowIn: ['**/ui/**'],
  requireOwnFolder: true,
}]
```

## When not to use it

If your components are single files rather than folders, or you do not colocate stories/tests with
components, disable this rule or trim `requiredSiblings` to just the pieces you do colocate.
