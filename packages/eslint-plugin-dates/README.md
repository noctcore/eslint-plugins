# @noctcore/eslint-plugin-dates

Calendar date rules: a calendar day (a due date, a leave day) read through the machine's time zone,
and hand-rolled day arithmetic outside the one calendar module that should own it.

**Docs:** [noctcore.github.io/eslint-plugins/packages/dates](https://noctcore.github.io/eslint-plugins/packages/dates/)

Not a good fit for code whose dates are all instants (log stamps, token expiries): it has no
calendar days to protect. Both rules match methods by name, without type information.

## Requirements

- ESLint 9 or 10, flat config (`eslint.config.js`) only.
- `configs.recommended` registers the plugin and sets rule severities, nothing else. It sets no
  `files` and no parser, so it applies to whatever files the rest of your config lints. To lint
  TypeScript, add a `files` pattern and `@typescript-eslint/parser`, as in the quick start.

## Install

```sh
bun add -D @noctcore/eslint-plugin-dates @typescript-eslint/parser   # or npm i -D / pnpm add -D
```

## Quick start

```js
// eslint.config.js
import tsParser from '@typescript-eslint/parser';
import dates from '@noctcore/eslint-plugin-dates';

export default [
  {
    ...dates.configs.recommended,
    files: ['src/**/*.{ts,tsx}'],
    languageOptions: { parser: tsParser },
  },
];
```

On its own this checks nothing: `recommended` enables neither rule, because both ban shapes your
calendar module has to use, so neither holds until `allowIn` names that module. Turn them on as
shown in [Opt-in rules](#opt-in-rules).

## Opt-in rules

Point `allowIn` at your calendar module, and optionally name it in the messages with
`calendarModule`:

```js
// eslint.config.js
export default [
  // ...the quick start's entry, then:
  {
    files: ['src/**/*.{ts,tsx}'],
    languageOptions: { parser: tsParser },
    rules: {
      'noctcore-dates/no-local-calendar-time': ['error', { allowIn: ['**/src/lib/calendar.ts'] }],
      'noctcore-dates/calendar-math-via-shared': ['error', { allowIn: ['**/src/lib/calendar.ts'] }],
    },
  },
];
```

`no-local-calendar-time` also takes `checks: [..., 'instantVsNow']` for a codebase where every
`Date` compared with the clock is a calendar day stored as midnight.

## Severity policy

Every rule is `error` or `off`, never `warn`: a warning is a rule nobody obeys. See the
[severity policy](https://noctcore.github.io/eslint-plugins/getting-started/#severity-policy).
