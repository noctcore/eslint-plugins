# @noctcore/eslint-plugin-nestjs

NestJS and BullMQ rules for the background work a request handler hands off: queue jobs that run
twice when a producer retries, queue and job names that drift between producer and worker,
schedules that run in whatever time zone the host happens to have, workers whose failures nobody
hears, and workers that are never closed on shutdown.

**Docs:** [noctcore.github.io/eslint-plugins/packages/nestjs](https://noctcore.github.io/eslint-plugins/packages/nestjs/)

Not a good fit for a codebase without `@nestjs/schedule` or BullMQ, where it does nothing.

## Requirements

- ESLint 9 or 10, flat config (`eslint.config.js`) only.
- `configs.recommended` registers the plugin and sets rule severities, nothing else. It sets no
  `files` and no parser, so it applies to whatever files the rest of your config lints. To lint
  TypeScript, add a `files` pattern and `@typescript-eslint/parser`, as in the quick start.

## Install

```sh
bun add -D @noctcore/eslint-plugin-nestjs @typescript-eslint/parser   # or npm i -D / pnpm add -D
```

## Quick start

```js
// eslint.config.js
import tsParser from '@typescript-eslint/parser';
import nestjs from '@noctcore/eslint-plugin-nestjs';

export default [
  {
    ...nestjs.configs.recommended,
    files: ['**/*.ts'],
    languageOptions: { parser: tsParser },
  },
];
```

## Opt-in rules

`recommended` leaves out the two queue conventions and the two queue-option rules: each is a team
decision before it is a defect, and a repo that has not made it would see every `queue.add`
reported. The conventions ask for a dedup key on every job and for shared queue and job names. The
option rules, `job-options-must-set-attempts` and `queue-options-must-set-retention`, ask every job
to state `attempts` (and a `backoff` when it retries), and `removeOnComplete` and `removeOnFail` (a
literal `false` included), in its options or in its queue's `defaultJobOptions` in the same file,
so they suit repos that construct their queues next to the code that fills them. Turn them on once
producers and workers agree on keys, names, retries and retention:

```js
// eslint.config.js
export default [
  // ...the quick start's entry, then:
  {
    files: ['**/*.ts'],
    languageOptions: { parser: tsParser },
    rules: {
      'noctcore-nestjs/queue-add-requires-dedup-key': ['error', { queuePattern: 'queue' }],
      'noctcore-nestjs/job-name-must-be-constant': ['error', { decorators: ['Processor', 'InjectQueue'] }],
      'noctcore-nestjs/job-options-must-set-attempts': ['error', { requireBackoff: true }],
      'noctcore-nestjs/queue-options-must-set-retention': ['error', { require: ['removeOnComplete', 'removeOnFail'] }],
    },
  },
];
```

## Severity policy

Every rule is `error` or `off`, never `warn`: a warning is a rule nobody obeys. See the
[severity policy](https://noctcore.github.io/eslint-plugins/getting-started/#severity-policy).
