# @noctcore/eslint-plugin-query

TanStack Query and tRPC rules for the client cache: invalidations that silently stop reaching
infinite queries, mutation callbacks that a detached observer never delivers, and mutations whose
failure nothing notices.

**Docs:** [noctcore.github.io/eslint-plugins/packages/query](https://noctcore.github.io/eslint-plugins/packages/query/)

Not a good fit for a codebase without TanStack Query, where it does nothing.

## Requirements

- ESLint 9 or 10, flat config (`eslint.config.js`) only.
- `configs.recommended` registers the plugin and sets rule severities, nothing else. It sets no
  `files` and no parser, so it applies to whatever files the rest of your config lints. To lint
  TypeScript, add a `files` pattern and `@typescript-eslint/parser`, as in the quick start.

## Install

```sh
bun add -D @noctcore/eslint-plugin-query @typescript-eslint/parser   # or npm i -D / pnpm add -D
```

## Quick start

```js
// eslint.config.js
import tsParser from '@typescript-eslint/parser';
import query from '@noctcore/eslint-plugin-query';

export default [
  {
    ...query.configs.recommended,
    files: ['**/*.{ts,tsx}'],
    languageOptions: { parser: tsParser },
  },
];
```

## Opt-in rules

`mutation-requires-error-handling` is left out of `recommended`: an app that handles every mutation
error in a global `MutationCache({ onError })` has nothing to fix, and the rule cannot see that
cache. Turn it on if your mutations handle their own errors:

```js
// eslint.config.js
export default [
  // ...the quick start's entry, then:
  {
    files: ['**/*.{ts,tsx}'],
    languageOptions: { parser: tsParser },
    rules: {
      'noctcore-query/mutation-requires-error-handling': ['error', { hooks: ['useMutation'] }],
    },
  },
];
```

## Severity policy

Every rule is `error` or `off`, never `warn`: a warning is a rule nobody obeys. See the
[severity policy](https://noctcore.github.io/eslint-plugins/getting-started/#severity-policy).
