# `rust-command-placement`

> A command handler attribute (default `#[tauri::command]`) may appear only in the allowed files, and never in the denied ones.

<!-- begin generated rule header -->
Runs under `@noctcore/harness`, not ESLint · Factory `createRustCommandPlacementRule` from `@noctcore/lint-meta-rules` · Category `source-text` · Fails CI by default: yes
<!-- end generated rule header -->

## Why

A command handler is an IPC surface: a function the frontend can call. When handlers are scattered
through persistence, primitive or type modules, the surface is impossible to review in one place, and
those modules pick up a dependency on the IPC layer they should never know about. Pinning handlers to
the command surface (an allow list), or keeping them out of the lower tier (a deny list), keeps the
surface reviewable.

### Opt-in

The rule is in `RULE_FACTORIES` and in `OPT_IN_RULE_IDS`, so a bare `createAllRules()` skips it. With
neither `allowIn` nor `denyIn` it reports nothing. Enable it through the factory:

```ts prose
import { createRustCommandPlacementRule } from '@noctcore/lint-meta-rules';

// Only under commands/.
const allow = createRustCommandPlacementRule({
  roots: ['apps/desktop/src-tauri/src', 'crates'],
  allowIn: ['apps/desktop/src-tauri/src/commands/**'],
});

// Anywhere but the lower tier.
const deny = createRustCommandPlacementRule({
  roots: ['src'],
  denyIn: ['src/store/**', 'src/store.rs', 'src/types/**', 'src/types.rs'],
  exclude: ['**/tests.rs'],
});
```

## What it flags

A `.rs` file under `roots` holding the command attribute (`attribute`, default
`#\[(?:tauri::)?command\b`, so `#[command]`, `#[tauri::command]` and
`#[tauri::command(rename_all = "snake_case")]` all match) when the file is outside `allowIn` (if set)
or inside `denyIn`. One violation per file, at the first attribute.

```rust
// allowIn: ['src/commands/**']

// Bad: src/store/files.rs
#[tauri::command]
pub fn read_file(path: String) -> Result<String, String> {
    store::read(&path)
}

// Good: src/commands/files.rs
#[tauri::command]
pub fn read_file(path: String) -> Result<String, String> {
    store::read(&path)
}
```

## What it does not flag

- The attribute spelled in a comment, a doc comment or a string literal, so a module doc that explains
  where commands belong is not a violation.
- Attributes inside a `#[cfg(test)]` module, unless `skipTestModules` is `false`.
- Files matching `exclude`, anything under `target/`, and every file when neither list is set.

## Options

```ts
createRustCommandPlacementRule(options?: RustCommandPlacementOptions): IMetaRule
```

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `id` | `string` | `'rust-command-placement'` | Rule id. |
| `roots` | `string[]` | `['src', 'crates/*/src']` | Directories whose `.rs` files are checked, recursively. |
| `allowIn` | `string[]` | `[]` | Globs where a command may live; a command elsewhere is reported. |
| `denyIn` | `string[]` | `[]` | Globs where a command must not live. |
| `attribute` | `string` | `#\[(?:tauri::)?command\b` | Regex source of the attribute that marks a command. |
| `skipTestModules` | `boolean` | `true` | Leave `#[cfg(test)] mod` blocks out of the scan. |
| `exclude` | `string[]` | `[]` | Globs of files never checked. |
| `ciCritical` | `boolean` | `true` | Whether a violation fails CI. |

## When not to use it

A codebase that keeps each feature's handlers next to the feature on purpose gets a false positive
for every handler from an allow list: use `denyIn` for the lower tier instead. The rule matches the
attribute as text, so a handler generated by a macro is not seen.
