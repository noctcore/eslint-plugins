- [#284](https://github.com/noctcore/eslint-plugins/pull/284) [`a231a8b`](https://github.com/noctcore/eslint-plugins/commit/a231a8b6c935ef4b151bb4417a433eab2e8f17fe) Thanks [@Shironex](https://github.com/Shironex)! - Every rule now names the weakness it reports: `meta.docs.cwe` (for example `['CWE-78']` on `no-shell-interpolation`), `meta.docs.owasp` (OWASP Top 10 2021, for example `['A03:2021']`) and `meta.docs.securitySeverity` (a CVSS-like score, for example `9.8`). Use it by path: `eslint -f ./node_modules/@noctcore/eslint-plugin-security/dist/sarif.js -o eslint.sarif .` (`dist/sarif.cjs` works too).

- [#287](https://github.com/noctcore/eslint-plugins/pull/287) [`21b1bc4`](https://github.com/noctcore/eslint-plugins/commit/21b1bc4ca73867d1508e762fde5414ec4207ea38) Thanks [@Shironex](https://github.com/Shironex)! - `no-user-controlled-redirect` now checks the other ways a server sends a redirect: `res.location(url)` and `Response.redirect(url)` (added to the default `redirectCallees`), and `Location` header writes on a receiver in the new `responseObjects` option (default `res`, `response`, `reply`): `set` / `header` / `setHeader` / `append` / `appendHeader` with the header name in any case (also held in a binding, `const L = 'Location'`, or behind a computed method), `set({ Location })`, `reply.headers({ Location })`, `setHeaders(new Map(...))` and `writeHead(status, [message,] headers)` with an object, a computed key or Node's array forms (`['Location', url]`, `[['Location', url]]`). A headers holder built earlier in the file is read too (`headers.Location = url`, `headers.set(...)`, `headers.push(...)`, `Object.assign(headers, ...)`), and so are the `headers` of `new Response(body, init)` and `new NextResponse(body, init)`. A sink after response-returning calls is read: `res.status(302).set('Location', url)`, `reply.code(302).header(...)`, `res.status(302).redirect(url)`.
  
  It also stops reporting targets proven to stay on a site, read where the value is used (`ok ? target : '/'`, a `const` boolean standing for its test, a `const` holding the target):
  
  - a URL whose `new URL(url).hostname` (or `.host` / `.origin`) was checked by an exiting `if`, or an `if` around the redirect, against `includes` / `has` / `===` on literals or an anchored regex whose every alternative ends in a literal domain of at least two labels, bounded by `^`, a dot or (for an origin) a literal `://` (`^(app|docs)\.example\.com$`, `^(?:[a-z0-9-]+\.)*example\.com$`; not `^[a-z0-9.-]*example\.com$`, which accepts `evilexample.com`, or `^[a-z]+\.com$`), with no change to the URL after the read (`u.host = x`, `Object.assign(u, ...)`, `Reflect.set`, an alias write or a helper call cancel it). A `hostname` / `host` check counts only for a `Location` header a `responseObjects` receiver writes, which browsers never follow to a non-http(s) scheme; `redirect()`, `NextResponse.redirect`, `Response.redirect` and `new Response(...)` need an `origin` check, because `javascript://app.example.com/%0aalert(1)` has an allowlisted host;
  - a same-site path: `startsWith('/')` while refusing `//`, `/\`, a tab, a line feed and a carriage return, or a regex starting `^\/` whose next character cannot be `/`, `\`, a tab or a line break;
  - a value read from an in-file `const` table of literal destinations (`TABLE[key]`, `MAP.get(key)`), or checked against a literal allowlist (with a query or fragment suffix);
  - a literal origin with no path followed by a value that starts with `/`, and the path of a URL object compared to a literal origin with `//` paths refused.
  
  The fixed-origin check shared with `no-user-controlled-fetch-url` now reads literal text the way the URL parser does: a tab or line break is dropped (`'/\t' + x` is a lone `/`), leading spaces and control characters are dropped, and extra slashes after `https:` still open the authority (`'https:///' + host`). Both rules report these now.
  
  A project spreading `recommended` can see new errors where it sets a `Location` header to a runtime URL; each is an open redirect unless the target is checked as above.

- [#288](https://github.com/noctcore/eslint-plugins/pull/288) [`0b35857`](https://github.com/noctcore/eslint-plugins/commit/0b358577c288064b8400ebaaad55cd54e3453011) Thanks [@Shironex](https://github.com/Shironex)! - `no-user-controlled-fetch-url` checks more HTTP clients by default: `axios(config)`, `axios(url, config)`, `axios.request(config)` and Node's `http.get`, `http.request`, `https.get` and `https.request`. The host can also be checked inline (`HOSTS.includes(new URL(url).hostname)`) or on a parsed `const u = new URL(...)` passed as `u`, `u.href` or `u.toString()` and not changed after the check. A `hostname` pin leaves the port open and redirects are still followed; the rule docs say how to pin those too.
  
  A project spreading `recommended` can see new errors on `http` / `https` / `axios` calls and sockets with a runtime target; each is an SSRF sink unless the target is fixed or checked as above. A project that set `fetchCallees` keeps its own list (the new client defaults do not apply) but gets the socket check.

  A project spreading `recommended` sees fewer errors, never new ones.

  unkeyed `createHash` digests (ETags, cache keys), comparisons against a literal, `undefined` or
  `null`, two secrets compared with each other (the double-HMAC defence) and length guards. It does
  not check `timingSafeEqual` for a missing length guard, since equal lengths often hold by
  construction and the syntax cannot tell.

  `require-sanitized-html` reports HTML reaching JSX `dangerouslySetInnerHTML`, `innerHTML`,
  `outerHTML` or `insertAdjacentHTML` unless the rule can see it is static markup, a same-file
  `const` bound to static markup, or the result of a sanitizer (`sanitizers`, default
  `DOMPurify.sanitize`, `sanitize`, `sanitizeHtml`, `xss`, `filterXSS`). It is opt-in because real
  code has trusted HTML no syntactic rule can prove safe, such as a syntax highlighter's output;
  name those producers in `trustedSources`.

  A project that spreads `recommended` will see new errors wherever an HMAC digest or Web Crypto
  signature is compared with `===` or `Buffer#equals` instead of `crypto.timingSafeEqual`.

- [`9c77a6b`](https://github.com/noctcore/eslint-plugins/commit/9c77a6b1695f002deddd6767e19fa2086c48babc) Thanks [@Shironex](https://github.com/Shironex)! - New rule `server-action-through-client`, shipped off and left out of `recommended`.

  In a module whose first statement is `'use server'`, every exported action must be built
  from an action client named in `actionClients` (`actionClient.inputSchema(...).action(...)`,
  `createServerFn().middleware([...]).handler(...)`), and no raw `export async function` may
  appear. A raw exported function is a public POST endpoint with no input schema, no error
  policy and no middleware, so no auth middleware either. The rule does not decide which client
  is right: a public form built from an unauthenticated client is correct code, and the client's
  name at the definition site is where a reviewer reads that choice.

  Inline actions (`async function x() { 'use server'; ... }` in a component body) cannot go
  through a client and are reported unless `allowInline` is set. Non-function exports, re-exports
  and modules without the directive are left alone. With an empty `actionClients` the rule accepts
  no client and reports every exported action, so enabling it without configuration is loud, not
  silent.

  No consumer's build changes: the rule is opt-in and needs per-project client names.
