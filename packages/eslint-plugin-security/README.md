# @noctcore/eslint-plugin-security

Injection, path-traversal, SSRF, open-redirect, XSS and timing-attack rules that match
high-precision syntactic sinks only; precision is the point.

**Docs:** [noctcore.github.io/eslint-plugins/packages/security](https://noctcore.github.io/eslint-plugins/packages/security/)

Not a good fit for a project that wants broad taint tracking; this plugin trades recall for reports
you can trust.

## Requirements

- ESLint 9 or 10, flat config (`eslint.config.js`) only.
- `configs.recommended` registers the plugin and sets rule severities, nothing else. It sets no
  `files` and no parser, so it applies to whatever files the rest of your config lints. To lint
  TypeScript, add a `files` pattern and `@typescript-eslint/parser`, as in the quick start.

## Install

```sh
bun add -D @noctcore/eslint-plugin-security @typescript-eslint/parser   # or npm i -D / pnpm add -D
```

## Quick start

```js
// eslint.config.js
import tsParser from '@typescript-eslint/parser';
import security from '@noctcore/eslint-plugin-security';

export default [
  {
    ...security.configs.recommended,
    files: ['**/*.{ts,tsx}'],
    languageOptions: { parser: tsParser },
  },
  // Optional: tune a preset rule's options.
  {
    files: ['**/*.{ts,tsx}'],
    rules: {
      'noctcore-security/no-shell-interpolation': ['error', { extraCallees: ['sh'] }],
    },
  },
];
```

## Opt-in rules

Five rules are exported but left out of `recommended`. Enable them, with your own options where a rule needs them:

```js
// eslint.config.js
export default [
  // ...the quick start's entries, then:
  {
    files: ['**/*.{ts,tsx}'],
    languageOptions: { parser: tsParser },
    rules: {
      // Opt-in only because a rule entering `recommended` is a major in 1.x; name your shared cookie config.
      'noctcore-security/auth-cookie-flags': ['error', { trustedConfigNames: ['AUTH_COOKIE_OPTIONS'] }],
      // Opt-in only because a rule entering `recommended` is a major in 1.x; raise minRounds to your policy.
      'noctcore-security/bcrypt-rounds-min': ['error', { minRounds: 12 }],
      // High false-positive rate; enable where request objects reach the filesystem.
      'noctcore-security/require-path-containment': ['error', { requestObjects: ['req', 'ctx'] }],
      // Name the HTML producers you trust.
      'noctcore-security/require-sanitized-html': ['error', { trustedSources: ['highlighter.codeToHtml()'] }],
      // Needs your action-client names; with none configured it reports every exported action.
      'noctcore-security/server-action-through-client': ['error', { actionClients: ['actionClient', 'authActionClient'] }],
    },
  },
];
```

### CWE ids and SARIF

Every rule names the weakness it reports in `meta.docs.cwe` (and its OWASP Top 10 2021 category in
`meta.docs.owasp`), so a SARIF consumer such as GitHub code scanning can classify a finding:

| Rule | CWE | OWASP |
| --- | --- | --- |
| `auth-cookie-flags` | CWE-614, CWE-1004, CWE-1275 | A05:2021 |
| `bcrypt-rounds-min` | CWE-916 | A02:2021 |
| `no-shell-interpolation` | CWE-78 | A03:2021 |
| `no-timing-unsafe-compare` | CWE-208 | A02:2021 |
| `no-user-controlled-fetch-url` | CWE-918 | A10:2021 |
| `no-user-controlled-redirect` | CWE-601 | A01:2021 |
| `presigned-post-requires-policy` | CWE-434, CWE-770 | A04:2021 |
| `require-path-containment` | CWE-22 | A01:2021 |
| `require-sanitized-html` | CWE-79 | A03:2021 |
| `server-action-through-client` | CWE-862 | A01:2021 |

`@microsoft/eslint-formatter-sarif` copies only a rule's docs URL, category and description into
SARIF, so the ids are lost there. The package ships a formatter that runs it and adds the tags code
scanning tools read (`security`, `external/cwe/cwe-078`, `external/owasp/a03:2021`) to every rule
that declares ids, from this plugin or any other. Install the Microsoft formatter next to the
plugin, then name the formatter by path (ESLint reads a scoped `--format` name as an
`eslint-formatter-*` package):

```sh
npm i -D @microsoft/eslint-formatter-sarif
npx eslint -f ./node_modules/@noctcore/eslint-plugin-security/dist/sarif.js -o eslint.sarif .
```

In code, `addTaxonomyTags(log, rulesMeta)` from `@noctcore/eslint-plugin-security/sarif` adds the
same tags to a SARIF log you already have.

## Severity policy

Every rule is `error` or `off`, never `warn`: a warning is a rule nobody obeys. See the
[severity policy](https://noctcore.github.io/eslint-plugins/getting-started/#severity-policy).
