# @noctcore/eslint-plugin-security

Injection, path-traversal, SSRF, open-redirect, XSS and timing-attack rules that match
high-precision syntactic sinks only; precision is the point.

**Docs:** [noctcore.github.io/eslint-plugins/packages/security](https://noctcore.github.io/eslint-plugins/packages/security/)

Not a good fit for a project that wants broad taint tracking; this plugin trades recall for reports
you can trust.

## Requirements

- ESLint 9 or 10, flat config (`eslint.config.js`) only.
- `configs.recommended` registers the plugin and sets rule severities, nothing else. It sets no
  `files` and no parser, so it applies to whatever files the rest of your config lints. To lint
  TypeScript, add a `files` pattern and `@typescript-eslint/parser`, as in the quick start.

## Install

```sh
bun add -D @noctcore/eslint-plugin-security @typescript-eslint/parser   # or npm i -D / pnpm add -D
```

## Quick start

```js
// eslint.config.js
import tsParser from '@typescript-eslint/parser';
import security from '@noctcore/eslint-plugin-security';

export default [
  {
    ...security.configs.recommended,
    files: ['**/*.{ts,tsx}'],
    languageOptions: { parser: tsParser },
  },
  // Optional: tune a preset rule's options.
  {
    files: ['**/*.{ts,tsx}'],
    rules: {
      'noctcore-security/no-shell-interpolation': ['error', { extraCallees: ['sh'] }],
    },
  },
];
```

## Opt-in rules

Six rules are exported but left out of `recommended`. Enable them, with your own options where a rule needs them:

```js
// eslint.config.js
export default [
  // ...the quick start's entries, then:
  {
    files: ['**/*.{ts,tsx}'],
    languageOptions: { parser: tsParser },
    rules: {
      // Opt-in only because a rule entering `recommended` is a major in 1.x; name your shared cookie config.
      'noctcore-security/auth-cookie-flags': ['error', { trustedConfigNames: ['AUTH_COOKIE_OPTIONS'] }],
      // Opt-in only because a rule entering `recommended` is a major in 1.x; raise minRounds to your policy.
      'noctcore-security/bcrypt-rounds-min': ['error', { minRounds: 12 }],
      // Opt-in only because a rule entering `recommended` is a major in 1.x; name your own escaper if the defaults miss it.
      'noctcore-security/no-unescaped-html-response': ['error', { sanitizers: ['escapeHtml', 'utils.escapeHtml'] }],
      // High false-positive rate; enable where request objects reach the filesystem.
      'noctcore-security/require-path-containment': ['error', { requestObjects: ['req', 'ctx'] }],
      // Name the HTML producers you trust.
      'noctcore-security/require-sanitized-html': ['error', { trustedSources: ['highlighter.codeToHtml()'] }],
      // Needs your action-client names; with none configured it reports every exported action.
      'noctcore-security/server-action-through-client': ['error', { actionClients: ['actionClient', 'authActionClient'] }],
    },
  },
];
```

### CWE ids and SARIF

Every rule names the weakness it reports in `meta.docs.cwe` (and its OWASP Top 10 2021 category in
`meta.docs.owasp`), so a SARIF consumer such as GitHub code scanning can classify a finding:

| Rule | CWE | OWASP | Security severity |
| --- | --- | --- | --- |
| `auth-cookie-flags` | CWE-614, CWE-1004, CWE-1275 | A05:2021 | 5.4 (medium) |
| `bcrypt-rounds-min` | CWE-916 | A02:2021 | 5.9 (medium) |
| `no-shell-interpolation` | CWE-78 | A03:2021 | 9.8 (critical) |
| `no-timing-unsafe-compare` | CWE-208 | A02:2021 | 5.9 (medium) |
| `no-unescaped-html-response` | CWE-79 | A03:2021 | 6.1 (medium) |
| `no-user-controlled-fetch-url` | CWE-918 | A10:2021 | 8.6 (high) |
| `no-user-controlled-redirect` | CWE-601 | A01:2021 | 6.1 (medium) |
| `presigned-post-requires-policy` | CWE-434, CWE-770 | A04:2021 | 6.5 (medium) |
| `require-path-containment` | CWE-22 | A01:2021 | 7.5 (high) |
| `require-sanitized-html` | CWE-79 | A03:2021 | 6.1 (medium) |
| `server-action-through-client` | CWE-862, CWE-20 | A01:2021 | 8.1 (high) |

The security severity (`meta.docs.securitySeverity`) is a CVSS-like score for a typical finding
of the rule, not a score of your code: command injection is critical, SSRF, an unauthenticated
server action and path traversal are high, the rest medium. Code scanning shows it as critical
(9.0 and up), high (7.0 to 8.9), medium (4.0 to 6.9) or low.

The package ships an ESLint formatter, with no dependency, that writes SARIF 2.1.0 with these
fields on every rule that declares them, from this plugin or any other: the tags code scanning
tools read (`security`, `external/cwe/cwe-078`, `external/owasp/a03:2021`) and
`security-severity`. Findings silenced with `eslint-disable` are kept as suppressed results, with
the text after `--` as the justification, and a file that does not parse is listed as an error
notification that marks the run unsuccessful. Name the formatter by path (ESLint reads a scoped
`--format` name as an `eslint-formatter-*` package); `dist/sarif.js` and `dist/sarif.cjs` both
work:

```sh
npx eslint -f ./node_modules/@noctcore/eslint-plugin-security/dist/sarif.js -o eslint.sarif .
```

Paths in the log are relative to the directory ESLint runs in, under the `SRCROOT` base id, which
`originalUriBaseIds` maps to that directory. Set `NOCTCORE_SARIF_ABSOLUTE_URIS=1` to write absolute
`file://` URIs instead. A file outside the directory always gets an absolute URI.

To see the findings in GitHub code scanning, run ESLint from the repository root, so the relative
paths match the checkout, and upload the log:

```yaml
- run: npx eslint -f ./node_modules/@noctcore/eslint-plugin-security/dist/sarif.js -o eslint.sarif .
  continue-on-error: true
- uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: eslint.sarif
    category: eslint
```

The job needs `permissions: security-events: write`.

## Severity policy

Every rule is `error` or `off`, never `warn`: a warning is a rule nobody obeys. See the
[severity policy](https://noctcore.github.io/eslint-plugins/getting-started/#severity-policy).
