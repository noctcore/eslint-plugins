`no-user-controlled-fetch-url` has two opt-in options, both off by default. `trustedSources`, meant for CLI and test code, names variables whose value the person running the program picks, such as a CLI config or flag (`trustedSources: ['config']`): the variable and every property read off it count as a trusted origin and a fixed host, unless the binding is a function parameter, is reassigned or has a property written (also through an alias such as `const c = config` or a global object), is handed to a call that may change it (`merge(config, req.body)`), or takes request data (`const config = req.body`, `res.locals`). Helpers are not followed, so handing the source to one ends the trust. `allowLoopback: true` trusts a URL whose author-written text names `localhost`, `127.0.0.1` or `[::1]` followed by a port the rule can see is a number (`http://127.0.0.1:${Number(port)}/health`). A runtime value is never trusted for looking like loopback.
