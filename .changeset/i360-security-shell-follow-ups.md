`no-shell-interpolation` reports three more shapes. A literal in a joi or zod chain that changes case is read as each case it can take, so after `Joi.string().valid('SUDO').lowercase()` the value may be the wrapper `sudo`. `spawn`, `spawnSync`, `execFile` and `execFileSync` with no `shell` option now read a shell program told to run a command: `spawn('sh', ['-c', cmd])` (also `bash -lc`, `/bin/sh -e -c`, `sh -o pipefail -c`, `bash --rcfile file -c`, `cmd.exe /c`, a shell started through `env` as in `spawn('/usr/bin/env', ['sh', '-c', cmd])`, and args held in a binding as in `const args = ['-c', cmd]; spawn('sh', args)`, reported whatever its elements when the binding may change before the call, as in `args[1] = x`, `args.push(x)` or `fill(args)`) checks the built command like `exec`, also when the command reaches the array through a holder, an element, destructuring, a local function that returns its parameter or a callback. A word built from a proven value that can spell a `find` action (`find . -${x}`) or a package runner's subcommand (`npm ${x} ${t}`) is read as one, so the words after it run as a program.
