`no-user-controlled-fetch-url` now reports more ways to move a request: options after the URL that the requester supplies (`https.get(url, req.body)`) or that `Object.assign` builds from a source the rule cannot read, each branch of a conditional options object, a `__proto__` the rule cannot read (it supplies every key the object does not set), a hook such as `agent` held by a `const` that is not author-written, the axios form methods (`postForm`, `putForm`, `patchForm`), every write to `axios.defaults` (a computed key, `Object.assign(axios.defaults, ...)`, replacing it whole, keys such as `proxy`), and undici's `new Client(origin)` and `new Pool(origin)`. Two hook shapes it reported before are now read as author-written, since the value is exact: an agent assigned to a `let` later (`let a; a = new Agent()`) and an agent handed to a single-parameter callback (`[new Agent()].forEach((agent) => https.get({ agent, ... }))`). One `Object.assign` shape is read as unchanged rather than reported: a fresh copy (`Object.assign({}, opts)`) passed straight into a call the rule reads (`https.get(url, Object.assign({}, opts))`), since no binding holds the copy and nothing can reach the nested values it shares with `opts`.
