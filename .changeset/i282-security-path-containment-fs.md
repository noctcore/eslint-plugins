'@noctcore/eslint-plugin-security': minor

`require-path-containment` (opt-in) now follows request-shaped input into filesystem calls, not only into `path.join` / `path.resolve`. The path argument of an `fs` call (`readFile`, `writeFile`, `unlink`, `rm`, `existsSync`, `watch`, `createReadStream` and the rest, sync, callback and promise forms), both paths of `rename` / `copyFile` / `cp` / `link` / `symlink`, and Express `res.sendFile` / `res.download`, is reported with the new message id `unguardedFsPath` when a `requestObjects` member reaches it through the function: bindings (every assignment), destructuring (also `const { query } = req` and a handler's destructured first parameter, `({ query }) => ...`), `for...of`, `+` and templates, member access, object and array literals (getters included), calls taking it, and `push` into an array. The fs module is recognised through static imports, `require`, dynamic `import()` (also inside a function), `import fs = require(...)`, aliases (`const p = fs.promises`), type wrappers and string keys. A local helper that passes its parameter to an fs path unchecked is reported at the call that hands it request input, with the new message id `unguardedFsHelper` (one call deep).

The flow stops at `path.extname`, a read from an in-file `const` table of literals, a confined schema output, `Number` / `parseInt` / `parseFloat`, a callee in the new `sanitizers` option, a value checked before the call against an allowlist or an anchored regex that admits no `/`, `\` or `:` and cannot match `.` or `..`, and `path.basename` only when its result is refused as `.` and `..` before the call (`basename('..')` is `'..'`). Those checks hold only for the checked value read as it is: below a member read or a call not known to keep its arguments' text (a decoder, `replace`, `slice`, `path.parse(x).name`, `basename(x, ext)`, `new URL(x)`, a helper), they no longer cut the flow. A `g` or `y` deny regex counts as a dot check only when it is a literal written at the test, and a `y` one is read as anchored at the start (`/\.$/y` does not refuse `..`). A request member checked against a literal allowlist is clean unless something writes it or hands an object on its path to other code. `res.sendFile(p, { root })` is checked on the root, which Express confines; Fastify's `reply.sendFile` / `reply.download` are checked only on a root the call passes.

The containment test is stricter, also for the existing join report: `startsWith` must compare with a base the requester does not pick that ends in a separator (`base + sep`), and a `path.relative` result must be refused both when it starts with `..` and when it is absolute. Before an fs call the test must run on every path to the call. A join with a direct `req.*` argument is still reported once, at the join.

The rule is not in `recommended`, so a project spreading `recommended` sees no new errors. A project that enabled it can see new reports on fs calls whose path is built from request input, on a bare `basename`, and on `startsWith(base)` tests without a separator.
