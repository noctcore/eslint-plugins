'@noctcore/eslint-plugin-security': patch
---

`no-unescaped-html-response` reads markup it used to skip. A constant template filled by `.replace` / `.replaceAll` at a string or plain regex placeholder is read with the value in place when `.replace` writes it as it is (a replacer function of the file, a constant without `$`, a number, `encodeURIComponent` output); any other replacement may apply `$` patterns that copy author text into its place, so it must be safe in a tag, and a later replacement is also judged where an earlier value may hold its placeholder. `.concat`, array accumulators (`rows.push(row)` then `rows.join('')`), every `return` of a `.map` callback or an in-file helper, and helper parameters (only while the helper does not write them) are read too.

A call or template tag from elsewhere (``layout(`<h1>${q}</h1>`)``, `dedent`, the common-tags `html` tag, a decoder) or a string method called on markup (`.slice`, `.padStart`, `.split`, `.trim`, a `.replace` that is not a placeholder fill) stays an opaque value, as before, but the markup it is given is now read where it stands, so an unsafe value in it is reported even with no author tag around the call, and every other value it is given must be safe in a tag. The call itself is reported where it lands when nothing inside it is. A string method called on markup counts as markup with no author tag around it.

New sinks: the return value of a Nest route handler (`@Get`, `@Post`, ..., also `@common.Get()` on a namespace import) without a non-HTML `Content-Type` header, `@Render`, `@Redirect`, `@Sse` or `@Res()`, since the Express platform sends a returned string as `text/html` (also reported on Fastify, which the rule cannot tell apart); the return value of a Fastify async handler once `reply.type('text/html')` is set; `new Response` whose headers are a `const` object or a `Headers` instance with `.set` / `.append`; a Koa body that starts with `<` on any branch of `?:`, `||` or `??`; and a write after `res.removeHeader('Content-Type')` or `ctx.remove('Content-Type')`.

The tokenizer now ends a comment at `<!-->`, `<!--->` and `--!>`, decodes character references before reading a URL scheme (`&#106;avascript:`, `javascript&colon;`) and reads it past any run of spaces, tabs and newlines (a URL start it cannot shorten below 256 characters counts as a script URL), counts a `data:` URL in an `iframe`, `frame` or `embed` `src` or an `object` `data` as code, and reads a URL in a meta refresh `content` (after an `http-equiv="refresh"`) and in SVG `animate` / `set` `to`, `from`, `by` and `values`. EJS `<%- locals["bio"] %>` and nunjucks `{% set b = bio | safe %}{{ b }}` are looked up like plain paths.

Reports removed: an array accumulator's `join`, and a `.map` callback or helper with several returns, are no longer reported as a whole when the markup they hold or return is safe (`rows.push('<li>' + escapeHtml(r.name) + '</li>')` then `'<ul>' + rows.join('') + '</ul>'` used to report the `join` call). When that markup is unsafe, the report moves from the whole call to the value inside it. The same goes for an opaque call: an unsafe value in the markup it is given, or another value it is given that may land anywhere, is reported instead of the call. Also, a value after `<!-->`, `<!--->` or `--!>` is judged as element text, where it is, rather than as comment text.
