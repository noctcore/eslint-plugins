Add the `github-actions-self-hosted-fork-guard` rule and its factory `createGithubActionsSelfHostedForkGuardRule`. It reports a `runs-on` that selects the `self-hosted` label (as a scalar, a flow list, a block list, a `labels:` mapping, or a quoted literal inside an expression), or an expression listed in `selfHostedExpressions`, in a workflow triggered by `pull_request` (as `on: pull_request`, a list, or a mapping key), when the `runs-on` value does not contain the fork guard, because a pull request from a fork would then run its code on the self-hosted runner. The guard is matched as a substring of `runs-on`, ignoring whitespace. A `pull_request_target` trigger, a GitHub-hosted label, an unlisted expression and a guarded `runs-on` are left alone, and a job-level `if:` guard does not count as the guard. It takes `workflowGlobs` (default `.github/workflows/*.y(a)ml`), `selfHostedExpressions` (default `[]`), `forkGuard` (default `!github.event.pull_request.head.repo.fork`) and `ciCritical` (default `true`). lint-meta has no `recommended` preset, and a caller that picks factories one by one sees nothing new. The factory is part of `RULE_FACTORIES`, so `createAllRules()` now includes it: a caller of `createAllRules()` sees a new violation on a `pull_request` workflow that runs on a self-hosted runner without the fork guard.
