`require-path-containment` reports more path-traversal shapes:

- A `sendFile` / `download` root that confines nothing is not a root, and the served path is checked instead: `'/'`, `''`, `null`, `path.sep`, the working directory or `/` written another way (`'.'`, `'.//'`, `'/.'`, `process.cwd()`, `path.resolve()`, `path.resolve('.')`, `path.join(process.cwd())`), or an environment value that may be unset or empty (`process.env.FILES`, `process.env.FILES ?? '/srv'`; `process.env.FILES || '/srv'` counts as a root). A spread after the root (`{ root: BASE, ...req.body.opts }`) or a spread options object with no `root` (Fastify `reply.sendFile('a.txt', { ...req.query })`) is checked as a root, and so is a later key that sets `root` again (``{ root: '/srv', [`root`]: req.query.r }``).
- Before a call that acts on a directory (`rm`, `rmdir`, `readdir`, `opendir`, `cp`, `rename`, `chmod`, `chown`, `symlink`, fs-extra `remove`, `emptyDir`, `copy`, `move`), a `path.basename` result must be refused as `''` as well as `.` and `..`: `basename('/')` is `''` and `join(BASE, '')` is `BASE`, so `rmSync(join(BASE, name), { recursive: true })` deleted the whole base.
- `fs-extra` and `fs-extra/esm` are fs modules, with their own path functions (`outputFile`, `readJson`, `remove`, `emptyDir`, `copy`, `move` and the rest), and a nested destructure `const { promises: { readFile } } = require('fs')` is followed.
- A helper with a destructured parameter (`function load({ name })`, `([name])`, by key for an object literal argument) or held in a `let` that is never reassigned is followed like one in a `const`.
- A method keeps a checked value's proof only when the value is its receiver (`name.toLowerCase()`) or it is `join` / `concat` on a literal (`[name, 'txt'].join('.')`): `qs.join(name)`, `lib.concat(name)` and `x.toString(name)` are new text. `String`, `encodeURI` and `encodeURIComponent` keep it only when they are the globals, not a local binding of that name. `new URL` and `fileURLToPath` are listed as decoders.
- An fs call that takes its path through a spread is read by position: `writeFile(...[dest], data)` checks `dest`. After a spread of unknown length every later argument may sit at a path position, so each is checked (`readFile(...args, name)`, `copyFile(...a, dest)`).

Reports removed: `writeFile(...[dest], data)` used to check `data` as the path, so request data written to a fixed path was reported; it is not now. These request-taint changes also apply to `no-user-controlled-fetch-url`, which shares them: a check on a URL part now holds through a local function that only returns its parameter (plain parameters, never reassigned; fewer reports), and no longer holds through `qs.join(part)`-style methods or a local `String` (more reports).
