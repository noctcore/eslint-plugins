Add the opt-in `test-files-require-source-sibling` rule and its factory `createTestFilesRequireSourceSiblingRule`, the complement of `test-sibling-enforcement`. It reports a colocated test whose source is missing: for each test under `roots`, the longest matching entry of `testSuffixes` is removed to get the base, and the test is reported when no `<base><ext>` exists for any entry of `sourceExtensions` and, with `directoryModules`, no `<base>/index<ext>` either. A folder with no `index` file does not count as the source. Tests outside every root, names with a suffix that is not listed (`.spec.ts` by default), paths under `node_modules` or `dist`, and tests matched by `ignore` are left alone. It takes `roots` (default `['src']`, globs such as `packages/*/src` allowed), `testSuffixes` (default `['.test.ts', '.test.tsx']`), `sourceExtensions` (default `['.ts', '.tsx', '.mts', '.cts', '.js']`), `ignore` (default `[]`), `directoryModules` (default `true`) and `ciCritical` (default `true`).

The factory is part of `RULE_FACTORIES` and is listed in the new `OPT_IN_RULE_IDS` export. `createAllRules()` takes a new optional argument, `createAllRules({ optIn: ['test-files-require-source-sibling'] })`, that adds named opt-in rules; a bare `createAllRules()` skips every id in `OPT_IN_RULE_IDS` and returns the same rules as before. lint-meta has no `recommended` preset, and a caller that picks factories one by one sees nothing new, so no existing caller sees a new violation.
