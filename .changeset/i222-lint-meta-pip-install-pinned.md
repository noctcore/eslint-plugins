Add the `github-actions-pip-install-pinned` rule and its factory `createGithubActionsPipInstallPinnedRule`. It reports each bare package of a `pip install`, `pip3 install`, `python -m pip install`, `python3 -m pip install`, `uv pip install` or `pipx install` in a workflow `run:` step, inline or in a block, and a `>=` or `~=` range with a message that asks for `==`, because an unpinned install resolves to whatever release is newest on the day CI runs. `\` line continuations are joined, and a command stops at `&&`, `||`, `;` and `|`. Flags, the value of a flag that takes one (`-r`, `-c`, `-i`, `--index-url`, `-t` and the like), tokens with `/`, `.txt` arguments, `.`, `-e .`, and a package that is a shell variable or a `${{ }}` expression are left alone, and `pkg[extra]==1.0` and `pkg==${VAR}` count as pinned. It takes `workflowGlobs` (default `.github/workflows/*.y(a)ml`), `installers` (replaces the default list) and `ciCritical` (default `false`). lint-meta has no `recommended` preset, and a caller that picks factories one by one sees nothing new. The factory is part of `RULE_FACTORIES`, so `createAllRules()` now runs it, but with `ciCritical` false by default its findings print as `[info]` lines and no project sees a new CI failure unless it passes `ciCritical: true`.
