`no-user-controlled-fetch-url` checks more HTTP clients by default: `axios(config)`, `axios(url, config)`, `axios.request(config)` and Node's `http.get`, `http.request`, `https.get` and `https.request`. An options or config object is read when it is an object literal or an in-file `const` that nothing changes before the call; later keys win, and a spread or computed key the rule cannot read is reported, since it may set any key.

Node's options are read the way Node picks the target: with `http.get(url, options)` the options override the URL, `hostname` wins over `host`, and `href` is not read on a plain options object. Every key that can move the request must be fixed: `hostname`, `host`, `port`, `defaultPort`, `protocol` and `socketPath`; a `path` must not start with `//` or hold a full URL from a runtime value; `agent`, `lookup` and `createConnection` must be author-written. An options object with none of these keys goes to localhost and passes.

axios configs are read in every call form, including `axios.get(url, config)`, `axios.post(url, data, config)`, `axios.create(config)` and the methods of a `const api = axios.create(...)` instance: `url` and `baseURL` must have a fixed origin, `socketPath` must be fixed and `proxy` must be `false` or name a fixed host. `axios.defaults.baseURL = x` is checked too. A config the rule cannot read is reported: `axios.create(getConfig())`, `axios.create(req.body)` or `axios.create(cfg)` with a parameter is an error, like a first-argument URL it cannot see. Type wrappers (`as`, `satisfies`, `!`, `<T>`) are seen through wherever an options or config object is read.

A new `socketCallees` option (default `net.connect`, `net.createConnection`, `tls.connect`) reports a socket whose host, port or IPC path is runtime, including an options object that overrides a positional host (`tls.connect(port, host, { host })`). Host reports use the message id `userControlledSocketHost`, and other target keys the new `userControlledRequestOption`.

It also stops reporting a host-pinned URL: one whose `new URL(url).hostname` (or `.host` / `.origin`) was checked by an exiting `if`, or an `if` around the call, against `includes` / `has` / `===` on literals or an anchored regex whose every alternative ends in a literal domain, with no write to the URL after the read. `new URL(pinned).hostname` passed as a host counts as pinned. The host can also be checked inline (`HOSTS.includes(new URL(url).hostname)`) or on a parsed `const u = new URL(...)` passed as `u`, `u.href` or `u.toString()` and not changed after the check. A `hostname` pin leaves the port open and redirects are still followed; the rule docs say how to pin those too.

A project spreading `recommended` can see new errors on `http` / `https` / `axios` calls and sockets with a runtime target; each is an SSRF sink unless the target is fixed or checked as above. A project that set `fetchCallees` keeps its own list (the new client defaults do not apply) but gets the socket check.
